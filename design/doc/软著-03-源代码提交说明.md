# 软件著作权登记 · 源代码提交说明

> 用途：说明向中国版权保护中心提交的源程序文档如何编排
> 配套工具：`tools/gen-copyright-source.py`（自动生成符合格式要求的源程序文档）

---

## 一、审查要求

中国版权保护中心对源程序材料的硬性要求：

| 项目 | 要求 |
|---|---|
| 页数 | **前 30 页 + 后 30 页**，共 60 页；源程序总页数不足 60 页时全部提交 |
| 每页行数 | 不少于 **50 行**（本工具按 50 行/页编排） |
| 纸张 | A4，建议使用等宽字体 9～10.5pt |
| 页眉 | 标注软件全称、版本号、页码（本工具已自动生成） |
| 内容 | 必须是真实源程序，不得用大段注释、空行或无关文本充数 |
| 命名 | 建议 `占地之王V1.0-源程序.doc/docx/pdf` |

> 注意：申请表填写的「源程序量」是**总行数**（约 4,500 行），与这里提交的 60 页不是一回事，不要混淆。

## 二、本项目源码构成

源程序全部位于 `src/` 目录，共 51 个 JavaScript 模块（实测约 29,800 行），另有根目录入口桩 `game.js`，按职责分层：

| 层级 | 目录 | 代表文件 | 职责 |
|---|---|---|---|
| 入口 | `src/` | `config.js` | 全局配置读取 |
| 游戏主类 | `src/game/` | `Game.js` | 主循环、状态机、屏幕切换、输入分发 |
| 世界 | `src/world/` | `HexMap.js`、`HexMath.js`、`HexTile.js` | 六边形地图与坐标数学 |
| 实体 | `src/entity/` | `Building.js`、`MarchGroup.js`、`AIPlayer.js` | 建筑、行军队伍、AI 对手 |
| 系统 | `src/system/` | `CombatSystem.js`、`PathfindingSystem.js`、`RenderSystem.js` | 战斗、寻路、渲染、输入、动画、音频 |
| 局外养成 | `src/meta/` | `PlayerProfile.js`、`ShopSystem.js`、`TechTreeSystem.js` | 存档、商店、科技、任务、招募 |
| 数据 | `src/data/` | `ConfigLoader.js`、`levels.js`、`races.js` | 配置加载、关卡与种族数据 |
| 网络 | `src/net/` | `CloudClient.js`、`SessionManager.js` | 云同步会话（原型期未启用） |
| 工具 | `src/utils/` | `math.js`、`rng.js` | 数学工具、确定性随机数 |

根目录 `game.js` 为微信小游戏入口桩（Canvas 创建与启动），仅 200 余行，建议并入源码文档首页以展示启动流程。

**不建议提交**的内容：`tests/`（测试脚本）、`tools/`（构建工具）、`config/*.js`（由 JSON 生成的配置副本）、`assets/`（二进制素材）、`preview/`（浏览器兼容层）。

## 三、自动生成源程序文档

本目录提供配套脚本，一键生成符合「前 30 页 + 后 30 页、每页 50 行、带页眉页码」要求的 HTML 文档：

```bash
python3 tools/gen-copyright-source.py
```

输出文件：

```
design/doc/占地之王V1.0-源程序.html
```

生成后用 **Microsoft Word 打开该 HTML 文件**（Word 可直接打开 HTML），确认分页与页眉无误后，另存为 `.docx` 或另存/打印为 PDF，即可随申请表提交。

### 生成规则

1. 按「入口 → 主类 → 世界 → 实体 → 系统 → 局外 → 数据 → 网络 → 工具 → 微信入口桩」顺序拼接源码；
2. 每个文件前加一行 `// === 文件路径 ===` 作为分界，便于审查员定位；
3. 每 50 行强制分页，页眉固定为「占地之王 V1.0 · 源程序 · 第 X / 60 页」；
4. 取拼接结果的前 1500 行（前 30 页）与后 1500 行（后 30 页）；若总行数不足 3000 行，则全部提交并在页眉注明实际页数；
   （本项目实测 29,904 行，已覆盖全部 52 个源文件，输出 60 页）
5. 代码中的 `<`、`>`、`&` 做 HTML 转义，中文以 UTF-8 编码写入，避免乱码。

## 四、提交前检查清单

- [ ] 运行生成脚本，确认输出文件存在且非空；
- [ ] 用 Word 打开，检查第 1 页与第 60 页是否为有效代码（非纯注释/空行）；
- [ ] 检查每页页眉的软件全称、版本号、页码是否正确；
- [ ] 检查中文注释无乱码；
- [ ] 另存为 `.docx` 或 PDF，文件名含软件全称与版本号；
- [ ] 申请表「源程序量」填写的是总行数，不是 60 页；
- [ ] 若源码近期有改动，重新生成后再提交，确保与登记版本一致。

## 五、常见问题

**Q：可以提交 PDF 吗？**
可以。中国版权保护中心接受 Word 或 PDF 格式的源程序文档。用 Word 打开 HTML 后「另存为 PDF」即可。

**Q：源码里带了很多中文注释，会不会影响审查？**
不会。注释是源程序的一部分，本工具的 50 行/页包含注释行。但不要用无意义的重复注释凑行数。

**Q：为什么只提交前后各 30 页？**
这是版权保护中心的固定规则——审查员只需核验代码真实性与著作权归属，不需要通读全部源码。

**Q：游戏用了分包，源码要不要体现？**
要。`game.js` 入口桩中包含分包加载逻辑（`wx.loadSubpackage`），已纳入文档末尾，能体现软件的技术特征。
