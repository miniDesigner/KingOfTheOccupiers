# 战斗兵种角色动画与队伍血条 · 美术规格（2026-11-25）

## 0. 结论先行

战斗单位当前不是「动画角色」，而是程序化圆盘 + 低透明度贴图叠加；队伍也没有血条。现已改为：**40 张真实兵种立绘做角色主体 + 渲染层四态变换动画 + 顶部队伍血条**，障碍格同时改为与翻开格同一套「立体石砖 + 染色 + 描边」表达。全部改动只在渲染层，不改任何玩法数值、坐标与点击命中。

**正式手绘序列帧属于另一项资源生产，未执行**——按项目铁律，出图前必须先给方案并等确认，见第 7 节。

## 2. 色彩板（本次用到的功能色，与 `ART-STYLE.md` 2.4 一致）

- 阵营：本地 `#3b82f6` / 敌方 `#ef4444`（沿用 `_ownerColor`）
- 品质 Q1–Q6：`#9ca3af / #22c55e / #3b82f6 / #a855f7 / #f97316 / #ef4444`

- 深底 `#1a202c` / 血条外框 `rgba(10,18,32,0.88)`

## 3. 障碍格改造

**问题**：旧 `drawObstacleTile` 只画深色六边形 + 山脉贴图，没有染色管线和描边，在棋盘上读成一块脱离体系的亮色卡片。

**改法**：与 `drawFlippedTile` 共用同一条管线——

1. 同款 312² 立体石砖（`tiles/mountain` 与 `tiles/hex_bright` 同角度同 placement）；
2. 贴图之上走 `_drawTileOwnerTint(x, y, '#64748b')`：alpha 0.45 中性染 + 3px 描边，与翻开格的蓝/红染完全同构；
3. 差异只在颜色语义：翻开格 = 敌我阵营色，障碍格 = 中性岩灰，读作「已揭示但不可占据」。

不新增贴图、不改 `HexMath` 几何、`BuildSystem.tryFlipTile` 仍以数据字段拒绝障碍。

## 4. 兵种四态动画规格

动画状态存在 `RenderSystem._unitActors`（`group.id → { bornAt, stateAt, state, shot }`），**绝不写回 MarchGroup**；`initBattle()` 调 `resetUnitActors()` 清零。

| 态 | 触发 | 时长/节奏 | 表现（世界坐标） | 结束条件 |
|---|---|---|---|---|
| 出生 birth | 队伍首次进入渲染视野 | 420ms | 缩放 0.55→1.0（back ease 轻微回弹）、alpha 0→1、抬升 8px 落位、阵营色扩散环 0.34R→0.76R 淡出 | 420ms 后转移动/攻击 |
| 移动 move | `state === 'marching'` | 135ms 一个踏步周期 | 上下 bob ±2.2px、轻微 squash ±2.5%、按行进方向倾斜 0.08rad | 状态切换 |
| 攻击 attack | `fighting_warrior` / `fighting_building` | 520ms/轮 | 前 22% 朝目标前冲 7px + 放大 12%，后 78% 回位；保留 ⚔ 标记 | 脱离交战 |
| 死亡 death | 队伍从 `marchGroups` 移除（含 destroyed/disbanded/arrived） | 560ms | 下沉 14px、alpha 0.85→0、旋转 0.45rad、缩小 18%、三点尘屑散开 | 560ms 后销毁快照 |

**朝向**：优先 `fightTarget.pixelX/Y`，否则 `targetPixelX/Y`；只用于动作方向，不改移动逻辑。

**角色尺寸**：`UNIT_ACTOR_SIZE = 46`（≈0.9 格），直径小于格心距 78px，多队堆叠不重叠。落地投影椭圆在角色下方，消除贴纸感。

## 5. 血条规格

- 位置：角色上方 `y - UNIT_ACTOR_SIZE - 4`，宽度 `baseRadius*2 + 8`
- 样式：高 4px、深色外框 1px、品质色描边 1px、灰白残量槽 + 三段填充色
- 比例口径：`warriors / max(_initialWarriors, 1)`，clamp 0~1；与治疗上限口径一致（治疗不会超过初始兵力）
- 兵力数字：`bold 14px` + 3px 深色描边，移到圆盘下方 `y + baseRadius + 9`，与角色不重叠
- 建筑血条 `drawHPBar`（3px）保持不变，队伍用独立 `drawUnitHPBar`，两条管线互不污染

## 6. 预算与验证

- 新增贴图：**0 张**。复用现有 40 张小图 + 3 张行走帧（行走帧仅留在资源层，战斗不再调用）。
- 每单位每帧额外绘制：1 投影椭圆 + 1 圆盘 + 1 立绘 + 1 血条（4 个矩形）+ 1 数字 ≈ 8 次，无粒子常驻；死亡瞬间 3 个尘屑点，同屏死亡 10 队 = 30 点，远低于 `AnimationManager.maxParticles=300`。
- 内存：动画状态 Map 每队约 5 个字段，常规同屏 < 30 队；死亡快照 560ms 自动回收。
- 回归：`node --test "tests/test-*.mjs"` → **109/109**；新增 `test-battle-unit-animation.mjs` 守护障碍管线、四态、血条、状态私有与开局清零。
- 实拍：430×932 + safeArea top44/bottom34，注入 5 障碍 + 4 队伍，确认角色清晰、血条可读、障碍与翻开格同族。

## 7. 正式手绘序列帧升级方案（待确认，未执行）

如果要的是**逐帧手绘的四态序列帧**而非程序化变换，需另立资源批次：

| 项 | 规格 |
|---|---|
| 范围 | 40 兵种 × 4 态，每态 4 帧（出生 4 / 移动 4 / 攻击 4 / 死亡 4）= 640 帧 |
| 单帧 | 96×96 RGBA 透明底，主体占画面 80%，与 `unit_small_XX` 同视角同光向 |
| 命名 | `units/anim/unit_<01..40>_<birth\|move\|attack\|death>_<01..04>.png` |
| 图集 | 按兵种 ID 每 16 帧一张 384×384 图集，共 40 张；运行时按状态/时间取帧 |
| 预算 | 40 张 × 384² RGBA ≈ 23.6MB 原始纹理；小游戏需压成 PNG-8 / ASTC，目标 ≤6MB |
| 红线 | 禁止 40 兵种共用一套通用帧；禁止改已确认的兵种配色与比例；AI 生成图需人工精修后验收 |

**需确认**：是否启动这 640 帧的生产？若启动，先出 1 个兵种（4 态 ×4 帧 =16 帧）作基准批，确认风格锚点后再放量——风格锚点没确认就批量生成 = 批量返工。
