## 一、为什么出、出什么

当前战斗棋盘已把带水印的占位图全部拦下（`_art()` 总闸），露出的是程序化兜底：深灰六边形 + 细描边 + `?` + 三角山剪影 + 汉字"兵/金/王/塔"。**干净但偏灰暗、缺质感**，是现在界面里最像"未上美术"的一块。

## 二、统一构图 / 视角 / 风格锚点（16 张必须共用）

这是出图铁律：**同一套表现结构，只在装饰与细节上递进**。16 张图必须像"同一美术师一次性画的整套"，不能一张一个视角。

### 2.1 全局锚点

| 维度 | 规范 |
|---|---|
| 风格语言 | Q 版厚涂，圆润软萌，糖果质感高光，**无硬黑描边**（深色仅作结构阴影 <1%）|
| 视角 | 地块：**正俯视六边形**（平面铺砖感，不做 3D 透视）；建筑：**2.5D 俯视微侧**（能看到屋顶 + 正面，约 25° 俯角）|
| 光源 | 顶部偏左上统一来光；亮部偏冷白，暗部用带色相深色（海军蓝 `#2B4A6F` 系），**禁纯黑** |
| 材质 | 地砖 = 光滑魔法石板/釉面；建筑 = 圆润糖果/塑料质感，明确高光点（对标幼龙身体反光）|
| 背景 | **透明底**，边缘干净无白边；导出前查 alpha |
| 尺寸 | 312×312，主体居中，四周留 ≥8% 透明安全边（防裁剪）|

### 2.2 风格锚点样本

以 `assets/units/unit_38.png`（幼龙）为**风格语言**锚点——只继承"圆润厚涂 + 糖果高光 + 无硬描边"，**不继承蓝紫配色**。出图时把幼龙作为参考图一起喂给生成器，确保家族感。

### 2.3 明度与配色基调 — V2 已确认：哑光青灰立体石砖（参考文明 7）

棋盘贴在**深靛夜景底**（大厅同款 `lobby_bg`，mean L≈34）上。

**V1 失败原因**：批 1 锚点走「亮青蓝 + 釉面高光」，实测主体中位 **L152**，用户反馈「太明亮，像冰块，不像地面」「过于平面化」。AI 把「亮青蓝石板」理解成发光玻璃/冰晶，且六边形裁剪贴花没有厚度。

**V2 基准（文明 7 表现）**：明格石砖 = 哑光青灰、有厚度侧面、柔和接地阴影的立体六边形瓦片。锚点实测主体中位 **L130**（p10=76 / p90=143），单位白高光点清晰可辨，石纹颗粒与细裂纹呈现石材而非玻璃。

- **地块整体走"哑光青灰石"基调**，明度集中 **L 90–150**（明格最亮 ~L130、暗格最暗 ~L76、可翻格居中），靠明度差区分状态，**不靠换色相**。
- 主色相：去饱和青灰 / 板岩蓝（`#6E8FA8` / `#4A6B85`）+ 暗部带靛蓝相避免纯黑；**禁亮青蓝釉面、禁玻璃/冰块通透感、禁 candy 高光、禁粉紫、禁荧光**。
- **立体结构**：每张地块图自带 pointy-top 六边形轮廓 + 明显厚度侧面（约占石砖高 15%）+ 柔和接地投影；渲染时**整图不裁剪**（详见 4.2）。
- **中央低细节区**：六边形顶面中央 60% 要干净（叠建筑 / 单位 / 文字 / HP 条），石纹与裂纹只做细微颗粒，不抢焦点。
- 建筑明度可略高（主体 L 60–110 + 高光），从暗石砖上跳出来。

> ✅ **V2 明格锚点已出并通过自检**：`hex_bright.png`（312×312，透明底，L130，去白底 + 去右下水印）。实机拼版见 `ANCHOR-v2-showcase.png`。其余 6 张地块据此基准递进。

## 四、生成与后处理路径

### 4.1 工具链（沿用本项目已跑通的图标链路）

1. **锚点先行**：先出 2 张基准锚点——`hex_bright`（地块基准）+ `barracks_2`（建筑基准）。V1 锚点因「冰块感/平面化」被否，V2 已重出 `hex_bright`（哑光青灰立体石砖，L130，文明 7 方向）；`barracks_2` 用户未提异议，沿用 V1。**V2 明格锚点确认后**再批量出其余 6 张地块 + 8 张建筑。
2. **图生图派生**：以锚点为参考图，逐张 prompt 强调"其余完全不变，只改指定部位；新部位与宿主共享光影/厚度/透视"。
3. **后处理**：
   - **棋盘石砖去背必须用 `tools/remove-board-bg.py`（V2 新增，勿用 remove-white-bg.py）**：AI 出图是带灰渐变的棚拍背景（RGB 223–255），`remove-white-bg.py` 按「白度 min(RGB)」判定会把浅灰背景误判成半透明，反解后在深底棋盘上呈现**灰白棋盘格噪点**（实机踩坑，见 `LIVE-battle-solid.png`）。新脚本按「青灰色相 + 明度」提取石砖与投影，背景一律丢弃，并紧裁到近满幅（满足 4.2 的 1:1 绘制标定）。
   - LANCZOS 统一到 **312×312**，主体居中，不横向拉伸；
   - alpha 校验：四角透明、实心主体 alpha=255、中间过渡仅限 1px 抗锯齿；
   - 右下角 AI 水印：紧裁后水印区（原图右下角）已被裁掉，**无需单独清理**（V1 那种大边距图才需要右下 alpha 清理）。批量每张仍要做拼版目检确认无水印残留。
4. **staging 审核**：产物先落 `.workbuddy/art-staging/board-art/`，出拼版图给你逐张确认，**确认后才覆盖 `assets/`**。

### 4.2 工程配套（必须同步做，否则正式图不显示）

上一轮的水印守卫是**按前缀一刀切**拦截（`WATERMARK_PREFIXES = ['tiles/', 'buildings/', ...]`）。正式图同名覆盖后，守卫仍会把它们拦下，画面不会变。方案配套两步：

1. **守卫改为精确 key 黑名单**：把 `tiles/` `buildings/` 从前缀名单移除，改成"逐张列仍带水印的具体 key"。出图并确认一张，就从黑名单划掉一张——颗粒度到单图，避免一次性放开把还没出图的水印也放出来。
2. **`_artHex` 渲染方式改造（V2 新增，已实机验证）**：石砖图自带六边形轮廓+厚度侧面，**不能再走 `drawHexShape + ctx.clip()`**（会把立体侧面切掉）。改为整图直接叠加。尺寸标定采用**图片紧裁 + 1:1 绘制**——`remove-board-bg.py` 把石砖紧裁到近满幅（顶面占图 98%），绘制尺寸 `2×HEX_SIZE/0.98≈106`（常量 `SOLID_BOARD_BODY_RATIO=0.98`）。**踩坑记录**：早期用未紧裁图（主体占 71%）+ 放大到 104/0.71≈146，结果石砖溢出到相邻格、侧面被后画的底色六边形切碎；紧裁后 1:1 绘制解决。翻格动画那处 `_art()` 也同步用同一 ratio。白名单 `SOLID_BOARD_KEYS` 只放已正式替换的 key，其余 tiles/ 继续拦水印。
3. **打开对应开关**：本轮 16 张全部到位并确认后，把 `config/game.json` 的 `artEffectDecor` 设为 `true`（或新建 `artBoardDecor` 独立开关，更干净），跑 `node tools/build-config-js.mjs`。**格子几何与点击命中全程不动**——改的只是贴图绘制尺寸与裁剪方式。
4. 兵种 `units/*` 不纳入名单，保持现状（按你的要求不出立绘）。
